## The single global model
### Feature Selection
The new dataset has doubled the number of stations thus doubled the amount of rows to train on, but the feature selection pipeline still default to 40, let's see if we should increase the number of features to train the model.

Turns out, increasing it to 50 not only increased the performance, but also reduced the previous problem of "dent in 2024" and the unweighted model performed better than the drifted model! 

#### Remove MI stage
- Seems useless that we literailly have to set k=300 for MI stage when we only have 400 features.
- It removes features that doesn't exhibit strong independent linear/non-linear relationships with the target (soil moisture), but the issue is, there're are many features provide critical joint signal when combined with other features, so it kind of doing the opposite of what we want.
- The heavy lifting is done by ElasticNet stage, that training mini models are more accurate validating the feature importance.

### Actually, don't remove MI stage!!!
- `derived_8.2-eval-1.1/` and `derived_8.2-eval-1.2/` performed worse than `OVERALL_SELECTED_FEATURES_V3`. 
- Without the pre-filtering of the Mutual Information stage, the ElasticNet selector is confused by the high collinearity of the full feature space. This results in a very sparse selection (only 34 non-zero coefficients), which stability bootstrap further trims to 32 stable features.
- Overall, the feature selection pipeline is weird, too few or too many `mi_k` will lead to poor performance by omitting important features (e.g. satallite); the model need to have both temporal and spatial features; lagged features are more stable.
- Its okay to set top-k high because we don't want to starv the model when there're plenty of stable features; and vice-verse if there's not enough features meeting the stability threshold, then it means something wrong with the prior pipeline stage.

# Plan: MLP Experiments on `derived_8.4` (1-regime + 2-regime) — `derived_8.4-eval-mlp-1.0`

## Goal

Test whether an MLP (PyTorch) can match or beat the current XGBoost baselines on the `derived_8.4` split, motivated by the hypothesis that XGBoost cannot extrapolate to unseen feature values. Run a multi-config hyperparameter sweep with parallel training on the H100 (80 GB), time everything, and produce a report in the same format as `derived_8.4-eval-1.1`.

**Scope (per user):**
- **1 regime** — Global single model on the 54-feature shared backbone (`shared_backbone_54`).
- **2 regimes** — best cluster config only: `Clustering_V0_Full_k2` winner (`c0=0, c1=10`): cluster 0 = 54 backbone feats; cluster 1 = 54 backbone + 10 delta feats (64 total).
- Multiple MLP hyperparameters, several models trained **in parallel** on the H100, process timed for future reference.
- The hyperparameter sweep is run for **both** 1-regime and 2-regime (same sweep configs evaluated in both families; winner picked per family).
- Same report format as `derived_8.4-eval-1.1` (leaderboard CSV, per-regime CSV, selected_features.json, diagnostics/station×year/yearly/loss-curve figures, README + notebook with markdown tables).

## Verified facts (from exploration)

- Data: `data/splits/derived_8.4/` — train 9803, val 4805, test 6620, trainval 14608; 7 WA stations; 2023–2025 test years; 495 raw feature columns; NaN is sparse (max 13.8% per column).
- H100 PCIe 80 GB available; `uv run` env has torch 2.12.0+cu130, CUDA works.
- `eval11` package (in `derived_8.4-eval-1.1/`) is importable: `load_experiment_data` gives splits, `shared_backbone_54`, `v0_features` (50), `candidate_pool` (96). `V0FullRouter` (KMeans k=2 on 50 V0 feats, seed 42) **reproduces eval-1.1 cluster counts exactly** (trainval 10624/3984, test 4817/1803).
- Cluster-1 delta features (10) are all in candidate pool and data columns; they are stored in `derived_8.4-eval-1.1/selected_features.json` (leaderboard record `Clustering_V0_Full_k2_c0_0_c1_10` → `cluster_1_additions`).
- XGBoost reference numbers to beat: Global Single (54 Backbone) pooled R² = **0.7792**; Clustering_V0_Full_k2 Winner (c0=0,c1=10) pooled R² = **0.8150** (from eval-1.1 `metrics_summary.csv`).
- Repo conventions (from `Models/Temporal/lstm/train_v9.py`): `SimpleImputer(median)` + `StandardScaler`, clip to [-5,5], AdamW + scheduler, early stopping, seed 42, `torch.save` best state dict, R²/RMSE/ubRMSE/Bias/MAE metrics.

## Implementation steps

### 1. Scaffold experiment dir + `mlp10` package
- `config.yaml`: reuse eval-1.1 `data:` / `model.seed` (42) blocks; add `sweep:` (curated config list, `n_parallel: 8`, `max_epochs: 200`, `patience: 25`, `holdout_frac: 0.10`, `checkpoint_every: 10`, seeds), `cluster_config:` (best cluster = `Clustering_V0_Full_k2`, c0=0, c1=10, delta list loaded from eval-1.1 json with explicit fallback), `xgboost_reference_file:` path to eval-1.1 `metrics_summary.csv`.
- `mlp10/model.py`: `MLPRegressor(n_features, hidden_sizes, activation, dropout, use_bn)` — reproducible init with seed; forward returns (batch,).
- `mlp10/data.py`: `build_tensors(...)` — `_clean_inf` → `SimpleImputer(median)` + `StandardScaler` fit on trainval (per cluster subset for specialists), clip [-5,5], raw target; returns np arrays + imputer/scaler; seeded station-stratified 10% holdout indices of trainval (fixed across configs).
- `mlp10/trainer.py`: `train_one_config(cfg, tensors, out_dir, resume=False)` — AdamW, cosine LR (or OneCycle), MSE loss (Huber as a sweep option), grad clip 1.0, early stop on holdout RMSE with patience; records per-epoch holdout + **test** RMSE curves (test curve diagnostic only, mirrors eval-1.1's test loss curves). **Checkpointing for resume**: every `checkpoint_every` epochs and at early stop, save `checkpoint.pt` (model + optimizer + scheduler + epoch + best state + curves + elapsed time); on `resume=True`, reload and continue from the saved epoch. Final artifacts per run: `best_model.pt` (state_dict), `preds.npy` (test), `curves.npy` (holdout+test RMSE per epoch), `meta.json` (config, epochs, best epoch, train_time_s, val_rmse, test metrics); `set_seed` everywhere, `torch.cuda.manual_seed_all`.

### 2. Parallel sweep over BOTH regimes (`run_mlp_sweep.py`)
- Driver: load data once (reuse `eval11.data.load_experiment_data`); compute 2-regime labels with `eval11.routers.V0FullRouter` (seed 42, verified to match eval-1.1). Preprocess once per feature set → save `artifacts/global_tensors.npz` (54 feats) and `artifacts/cluster_tensors.npz` (per-cluster feature sets: c0 = 54 feats, c1 = 64 feats) with fixed holdout indices. Workers never redo pandas/preprocessing.
- Each sweep config is trained in **both families** (job = family × config):
  - **Family A — 1 regime**: single global MLP on the 54 backbone feats (trainval, holdout early stop, test eval).
  - **Family B — 2 regimes** (best cluster config `Clustering_V0_Full_k2` c0=0,c1=10): two per-cluster specialists (c0: 54 feats, c1: 64 feats); each specialist trains on its cluster's trainval rows with its own cluster holdout; pooled holdout RMSE = sqrt(Σ (n_c/N)·holdout_rmse_c²) (same weighting eval-1.1 uses for combined curves) is the selection metric.
- Spawn a **queue of subprocess workers** (`subprocess.Popen`, cap `n_parallel=8`); each worker trains one job, writes artifacts to `models/<family>/<config_id>/`, checkpoints every `checkpoint_every` epochs. **Resume**: `--resume` skips completed jobs and continues in-progress ones from `checkpoint.pt` (driver also re-derives the pending job queue from what's on disk). Log per-worker stdout to `artifacts/logs/`.
- Rank by holdout RMSE per family → `sweep_results.csv` (family, config, holdout_rmse, test_r2/rmse/bias/mae, epochs, best_epoch, train_time_s).
- Monitor GPU during run (`nvidia-smi`); bump `n_parallel` if utilization is low.
- All 26 curated configs (documented in config.yaml): width/depth {[64,64],[128],[128,128],[256],[256,256],[512],[512,256],[512,256,128],[1024,512,256]} × lr {1e-4,3e-4,1e-3} × dropout {0,0.1,0.3} × wd {0,1e-4,1e-3} × batch {256,512,1024} × activation {silu,relu} × loss {mse,huber} — curated into ~26 concrete configs around the anchor ([256,256], silu, d=0.1, lr=3e-4, wd=1e-4, bs=512). Same configs run through both families.
- Optional cheap add-on: re-run each family's winner with seeds {42,7,123} for a stability note.

### 3. Winner selection + full report artifacts (`run_mlp_eval.py`)
- No retraining needed: the sweep already produced test predictions/curves/models for every (family, config) job; winners are the sweep-trained models (early-stopped on holdout, evaluated on test).
- Pick top-N per family (e.g., top-3 1-regime + top-3 2-regime) for the leaderboard.
- Save `metrics_summary.csv` (MLP rows + XGBoost reference rows loaded from eval-1.1 CSV, tagged as reference), `per_regime_metrics_summary.csv` (for 2-regime winners: per-cluster n_train/n_test/r2/rmse/ubrmse/bias/mae, reuse `eval11.evaluator.compute_metrics`), `sweep_results.csv`, `selected_features.json` (same schema as eval-1.1: shared_backbone_54 + cluster additions + leaderboard).
- Generate figures: `diag_*.png` (winner per family), `per_regime_diag_*.png` (2-regime winner), `station_year_*.png` (reuse `generate_station_year_table`), `yearly_r2_linechart.png`, `loss_curves_*.png` (test RMSE per epoch), `sweep_*.png` (holdout/test RMSE vs config, per family).
- Write `timing_log.json` (per job train_time_s + sweep total + eval total + wall clock) and `timing_summary.csv`.

### 4. Extrapolation diagnostic (`analyze_extrapolation.py`)
- Light, secondary section addressing the motivating hypothesis: for the best MLP per family and best XGBoost (2-regime winner), flag test rows whose values on the top-gain features (from candidate pool) fall outside the trainval [min,max] range; report pooled + OOD-slice RMSE/R² + an `ood_*.png` figure. Also surfaces per-station/per-year gaps already in the tables.

### 5. Report notebook + README (same format as eval-1.1)
- Notebook `derived_8.4-eval-mlp-1.0.ipynb` (via `nb create`/`nb cell`): markdown sections + code cells printing markdown tables from the CSVs — Overall Leaderboard (MLP + XGBoost refs), Hyperparameter Sweep Summary per family (1-regime and 2-regime; replaces eval-1.1's delta grid), Per-Regime Breakdown, Yearly Breakdown, Extrapolation note, Timing.
- `README.md` mirroring eval-1.1's README structure (Objective / Leaderboard / Sweep table per family / Per-Regime / Yearly / Timing / Key Takeaways), with tables populated strictly from executed-notebook stdout (AGENTS.md reproducibility rule).
- Before finishing: run `nb execute` from `notebooks/` to verify the notebook runs end-to-end.

## Runtime estimate (2h budget)

- Each MLP training run: ~26 steps/epoch (bs 512, ~13.1k train rows after holdout), ≤200 epochs → a few thousand steps ≈ **5–30 s** on H100 (cluster-1 specialist: ~4k rows → even faster).
- 26 configs × 3 trainings (1 global + 2 specialists) ≈ **78 jobs**; at 8-parallel ≈ 10 waves ≈ **~10–30 min** GPU. XGBoost refs already exist (no retraining). Total compute well under 2 h — the bulk of the time is code + report + notebook verification, which fits comfortably. All training is checkpointed/resumable and timed.

## Risks / notes

- XGBoost handles NaN natively; MLP needs imputation — using trainval-median impute + standard scaling, documented in README (this is a fair preprocessing difference, not a tuning trick).
- eval-1.1 fit on full trainval with fixed 2500 iters; MLP early-stops on a seeded 10% holdout of trainval — documented for comparability.
- GPU nondeterminism: seeds set everywhere; optional 3-seed rerun of the winner for variance reporting.
- Only new files are created under `notebooks/experiment/derived_8.4-eval-mlp-1.0/` (plus nothing else modified); imports reuse `eval11` (no edits to eval-1.1 files). Nothing versioned is modified.

# Plan: `derived_8.4-eval-mlp-2.3` — final frontier check for the mlp-2.0 architecture: 320²-hubergelu/lr6e-4 cell refinement + full-3-seed pool (~1.75 h wall, `gpu_debug` H100)

## 1. Analysis of `derived_8.4-eval-mlp-2.2` (what we learned; drives every 2.3 decision)

### 1.1 Headline results (from the executed 2.2 notebook / README)

- **2.2 is an honest negative on the val-selected winners — but found the
  strongest single MLP of the whole 1.0–2.2 series on test.** 3-seed val
  winners: mixed `w512x512x512_d0.3_huber0.03_lr1e-3` → test R² 0.7809
  (below 2.1's 0.7844), 54 `w448x448x448_d0.3_huber0.1_gelu_lr1e-3` → 0.7596
  (below 2.1's 0.7713), 96 unchanged 0.7595. 2.2's mixed val top-5 ensemble
  0.7850 and cross-family 0.7885 both sit below 2.0's 0.8003 / 0.7932.
- **The test-best single is the 54-family `w320x320_d0.4_huber0.2_gelu_lr6e-4`
  → 0.7973** (3 seeds, val rank 49/82!), with `w320x320_d0.4_gelu_lr6e-4`
  0.7960, `w320x320_d0.3_huber0.2_gelu_lr6e-4` 0.7943, `w320x320_d0.3_gelu_lr4e-4`
  0.7942, and the mixed `w448x448x448_d0.3_huber0.1_gelu` 0.7940 close
  behind. **The 320²-hubergelu/lr6e-4 cell is the new frontier — and it is
  invisible to the val selector.**
- **Val-year diagnostic (headline finding): the official val split's 2022
  half is the noise source for the 54/96 families.** Spearman(val-2021,
  test) = +0.747 (96) / +0.454 (54) while val-2022 = +0.106 / +0.133 (both
  ns); the full-val mean dilutes the reliable 2021 signal. The mixed family
  is different: BOTH years are negatively correlated with test (−0.249 /
  −0.352) — its val-noise is structural (the c0 = 96-pool half). Diagnostic
  only; the deployed rule is unchanged.
- **54-family selection signal flipped positive: +0.582 at 3 seeds (2.1:
  −0.555)** — but the 2→3-seed flip still moved the 54 winner to a
  worse-test config (0.7772 → 0.7596). **The 54 val top-10 is dominated by
  3-layer configs that overfit val and fail on test** (3-layer 54 test range
  0.7596–0.7790 vs the 2-layer 320² frontier 0.79+); the val selector keeps
  picking the wrong cell.
- **Debias: 54 met (median 3.1 %), mixed improved (12.7 → 9.6 %) but still
  >5 %; 96 worsened (13.9 → 21.7 %).** The mid-lr {4e-4, 6e-4, 8e-4} 96
  small-net configs are more biased than the lr3e-4 anchor (w256x256_d0.5:
  1.1 %, test-best 0.7834); the max_epochs {500, 600} probes hurt
  (me500 → 0.7682 vs the 400-cap 0.7834). **The lr3e-4 small-net pool IS the
  debiased 96 region** — the 2.3 96 grid is lr3e-4-dominated by construction.

### 1.2 The evidence that shapes the 2.3 sweep (from `sweep_results.csv`)

1. **The 54-family frontier is the 2-layer 320²-hubergelu/lr6e-4 cell** — at
   320², gelu+huber: d0.4/δ0.2 → 0.7973, d0.3/δ0.2 → 0.7943, d0.4/δ0.1 →
   0.7922, d0.3/δ0.05 → 0.7850 (val rank 9 — the only val-visible one);

   8e-4} at any δ; d0.5; widths 288/352 at huber; lr5e-4 everywhere in 54.**
2. **The 54 small-net region (192²–256², gelu, lr4e-4/6e-4) is nearly as
   strong and nearly unbiased** — w192x192_d0.3_gelu_lr4e-4 0.7934
   (bias²/MSE share 0.02 %!), w192x192_d0.3_gelu_lr6e-4 0.7933, w224x224_d0.4_gelu_lr6e-4
   0.7919, w224x224_d0.3_gelu_lr6e-4 0.7914 — at 1/2 the params of 320².

3. **The mixed-family frontier is the gelu 3-layer cell at lr3e-4/4e-4** —

- **2-layer mixed at lr {6e-4, 1e-3}** (0.71–0.76) — probed only at

## 2. Objective & success criteria

**Objective:** `derived_8.4-eval-mlp-2.3` — an *optimization + further
parameter sweep* of the 2.2 frontiers, temporal protocol only (same honest
protocol as 2.0/2.1/2.2; no LOSO), answering **"is the mlp-2.0 (2-regime)
architecture still meaningful?"** The sweep is sized to spend ~1.75 h of the
`gpu_debug` H100 wall allocation (the allocation is otherwise wasted): ~225
phase-1 configs × **3 seeds for EVERY config** (the user's explicit ask —
2.2 left most configs at 2 seeds; only the top-M had 3, which limited the
3-seed val-year/selection diagnostics to a subset) + champion ≈ **~690
job-seeds ≈ 8.5 GPU-h ≈ ~85 min sweep ≈ ~1.6 h total wall** at 8 workers.

Success criteria (honest, val-based):
1. **Val-selected 3-seed winner or val top-k ensemble test R² > 0.8003**
   (2.0's mixed val top-5 ensemble — the bar 2.1 and 2.2 missed; 2.2's best
   val-selected single 0.7809, cross-family 0.7885) **and/or 54-family
   val-selected winner test R² ≥ 0.79** (2.2's 54 winner collapsed to 0.7596
   while the test-best cell sits at 0.7973 — closing that gap is the 54
   objective; with the 3-layer val-overfitters gone from the pool and full
   3-seed coverage, the val selector should finally see the 320² frontier).
2. **Debias:** 96-family median bias²/MSE < 5 % (2.2: 21.7 %; the 2.3 pool
   is lr3e-4-small-net-dominated by construction, anchor 1.1 %). Reported
   honestly either way.
3. **Selection reliability:** full-pool 3-seed Spearman(val, test) per
   family; the val-year diagnostic now covers the ENTIRE pool at 3 seeds
   (2.2's was restricted to the phase-3 subset, n=26–42/family); winner
   flips across seed depth documented.
4. **Reproducibility:** anchors bit-identical vs 2.2 (stack check via
   `compare_anchor_vs_2.2.py`, max|diff| = 0 target); `nb execute --uv` from
   `notebooks/`; README tables from stdout.

## 3. What's new in 2.3 (code changes vs 2.2)

### 3.1 No training-path changes — `mlp23/` is a byte-identical copy of `mlp22/`
- The mlp22 trainer already saves best-val predictions (`val_preds.npy`) and
  the sweep already saves `artifacts/val_meta.npz`. Nothing in the training
  loop changes → **anchors' val curves stay bit-identical to 2.2** (proved
  by the offline stack check; cross-node caveat as before).
- `mlp23/trainer.py` docstring updated to data_version 10; model/data/
  feature_groups/plots copied unchanged.

### 3.2 Full-3-seed pool (the user's ask; the structural mitigation for 2.2's val-noise findings)
- `sweep.phase2_top_n` and `sweep.phase3_top_n` are set to the **deduped
  family sizes** (printed by `make_configs.py`), so every config trains
  seeds {42, 7, 123} — the 3-seed mean val RMSE becomes the honest signal
  for the ENTIRE pool (2.2: only top-42/26/40 had 3 seeds). Phases stay
  intact (phase 2 = seed 7, phase 3 = seed 123, ranked by the phase metric);
  the phase machinery is unchanged, only the top-Ns are now caps.
- `analyze_selection.py`'s Spearman-by-aggregation-depth and
  `analyze_val_years.py`'s per-year diagnostics therefore cover the full
  pool at all three depths — stronger statistics than 2.2, no new code.

### 3.3 Sweep driver / grids
- `make_configs.py` (committed): new grid spec (section 5) → `config.yaml`
  (data_version 10; always emits `hidden_sizes`; `max_epochs` when ≠ 400;
  `champion_top_n: {2regime_mixed: 2, 2regime_54: 3, 2regime_96: 1}` —
  the 54 gets the deepest champion hedge because its val noise is the
  documented problem; `mlp22_reference_file`).
- `run_mlp_sweep.py` / `run_mlp_worker.py` / `run_mlp_champion.py`: copies
  of 2.2 with the mlp23 import; phases, `--resume`, per-job logs,
  `seed_complete`/`seed_resumable` invalidate-and-retry unchanged.
- `run_mlp_eval.py`: adds `load_mlp22_references` via
  `mlp22_reference_file: notebooks/experiment/derived_8.4-eval-mlp-2.2/metrics_summary.csv`
  (val-selected winners, test-best refs, val top-3/5/10, 5-seed champ,
  cross-family rows → `MLP_2.2_Reference`); 2.1/2.0/1.3/XGBoost refs kept.

### 3.4 New offline script — `compare_anchor_vs_2.2.py`

### 3.5 Kept (proven) ingredients — unchanged from 2.0/2.1/2.2
huber δ {0.05, 0.1, 0.2} (+0.15/0.25/0.3 probes for 54); gelu/silu; dropout
0.2–0.6; AdamW + warmup 5% + cosine; grad clip 1.0; patience-60;

per-job logs.

### 3.6 Explicitly out of scope
LOSO (per the brief and "same protocol"); new routers / station embeddings /
feature selection (96-pool / 54-backbone / 10 deltas pinned); SWA (closed
negative); fg/plr (closed negatives); 54 3-layer (2.2 negative, anchor
excepted); 96 mid-lr / huber / mixup / me{500,600} (2.2 negatives);
2-layer mixed at lr{6e-4, 1e-3} (2.2 negative); lr1e-4 anywhere; changing
the val-selection rule (val-year analysis is diagnostic only).

## 4. Protocol (data_version 10, temporal only — same honest protocol as 2.2)

- Train on official train (2017–2020, n=9,803); early-stop/select on official
  val (2021–2022, n=4,805); evaluate on untouched test (2023–2025, n=6,620).
  aux2020 (n=2,519) diagnostic only.
- Phase 1: seed 42 for every (family × config). Phase 2: seed 7 for the
  top-N per family by 2-seed-able val RMSE (N = family size → all configs).
  Phase 3: seed 123 for the top-M per family (M = family size) →
  **3-seed mean val RMSE winner selection** (unchanged rule).
- Winner pool = mlp/fg/plr (mlp-only in practice — no fg/plr configs run).
- Champion step: 5-seed {42, 7, 123, 2024, 999} ensembles of the val-selected
  winners (mixed top-2 + 54 top-3 + 96 top-1); offline val top-k (3/5/10) +
  cross-family ensembles, unchanged.

## 8. Risks & mitigations

- **The 54/mixed val noise persists** — structural, per 2.2 (mixed's
  val–test correlation is negative in both val years). 2.3's mitigation:
  full-3-seed pool (the 3-seed mean is now computed for every config, not a
  subset), the 3-layer val-overfitters removed from the 54 pool (the
  documented cause of the 2.2 winner collapse), and the deeper 54 champion
  hedge (top-3). If the winner still flips, it is reported honestly.
- **96 debias misses <5 %** — the pool is lr3e-4-small-net-dominated by
  construction (the only region 2.2 found debiased); reported honestly
  either way.
- **Sweep lands short of / over the ~1.75 h target** — the grid is the
  sizing knob; `--resume` protects the run; the 2:00:00 partition cap is
  the hard limit (2.2's node achieved 0.135 jobs/s; if slower, phase-3
  tails complete in a `--resume` follow-up).
- **`gpu_debug` occupancy** — 2–3 H100s shared with other users (2 running
  + 2 pending jobs at plan time); the job may queue; the 2 h limit bounds
  only our runtime. If the partition stays full, ask the user before any
  fallback.
- **Cross-node bit-identity not guaranteed** (PTX-JIT/driver/cuDNN) — the
  anchor stack check is evidence (2.1 reproduced 2.0 and 2.2 reproduced 2.1
  exactly on different nodes); reported with the same caveat.
- **~690 jobs is a long, failure-prone run** — resumable per phase,
  per-job logs, `seed_complete`/`seed_resumable` invalidate-and-retry; a
  single worker crash only costs that job.

# Plan: `derived_8.4-eval-mlp-2.1` — optimize the mixed family + fair SWA re-test + finish the 96-family debias (sweep sized to ~1 h wall)

## 1. Analysis of `derived_8.4-eval-mlp-2.0` (what we learned; drives every 2.1 decision)

### 1.1 Headline results (from the executed 2.0 notebook / README)

- **The ceiling is broken by the `2regime_mixed` family** (c0 = 96-pool, c1 = 54+10):
  honest mixed-family **val top-5 / top-3 ensembles → test R² 0.8003** (vs 1.3's honest
  ceiling 0.7825); the 2-seed honest single `w512x512x512_d0.3_huber0.1_swa` (mixed) →
  **0.7903** (past the 1.3 test-best 0.789 with honest val selection). Cross-family
  (54+96+mixed) ensemble 0.7932. XGBoost 2-regime reference 0.815 (itself test-selected).
- **2025 is fixed**: mixed val top-3/top-5 ensembles post 2025 R² 0.8336/0.8324 — best of
  any model, beating XGBoost 2-regime (0.8303) on the historically weakest MLP year.
- **Per-cluster allocation hypothesis confirmed**: mixed c1 (54+10) holds the 54-family's
  ~0.83 R² (median 0.8315) while c0 (96-pool) reaches 0.7726.

### 1.2 Documented negatives from 2.0 (do NOT re-spend GPU on these)

- **`fg` (grouped towers) and `plr` underperform the plain MLP** at this scale: fg best
  0.782, plr best 0.720 vs plain-MLP 0.790. The winning lever was the *feature
  allocation*, not the tower structure.
- **SWA as configured (2.0 recipe) is a negative**: `swa_start_frac: 0.6` equal-weight
  averaging over epochs 240–400 + BN recalibration → **no SWA snapshot ever beat the live
  best on val** (SWA val 0.070–0.126 vs live 0.045–0.062). The deployment *mechanism*
  worked (it correctly rejected every snapshot). The 2.0 README itself prescribes the two
  fixes for a fair re-test: **(a) start averaging later (`swa_start_frac ≈ 0.85`)** and
  **(b) guard the RNG around the BN-recalibration pass** so a swa job's live trajectory
  stays bit-identical to its anchor. Both are implemented in 2.1 (section 3.1).
- No calibration, no trainval retrain, patience-60 kept, aux2020 diagnostic-only
  (1.2/1.3 negatives — honored, unchanged).

### 1.3 The evidence that shapes the 2.1 sweep (from `sweep_results.csv`)

1. **Mixed family wins, but its val ranking is noisy.** Spearman(val_rmse, test_r2) per
   family: 96 −0.042 (p=0.907), 54 +0.549 (p=0.100), **mixed −0.455 (p=0.187)**. For
   mixed, the val top-2 are `fg` configs (test 0.760/0.782) while the test-best is the
   val-3rd `w512x512x512_d0.3_huber0.1_swa` (0.7903). Consequences (protocol-safe):
   (a) drop the documented-negative `fg`/`plr` configs from the pool — a large share of
   the val/test disagreement disappears without touching the selection rule; (b) much
   denser multi-seed coverage of the mixed family in phases 2–3 (seed-averaging is the
   only honest way to beat single-seed val noise).
2. **The winning mixed configs sit in a narrow region.** Best val+test mixed MLPs:
   `w512x512x512_d0.3_huber0.1` (val 0.04949, test 0.7789), its `_swa` variant (val
   0.04945, test **0.7903**), `w384x384_d0.3_gelu` (test 0.7790), `w448x448_d0.3_gelu`
   (test 0.7605). 2.1 sweeps this region as structured 2-factor grids: shape × lr,
   loss × dropout, wd × mixup, act × depth, lr × huber.
3. **96-family debias = capacity control, and it is near-done.** `<200k`-param bucket:
   median test R² 0.7844, median bias 0.0072; `w256x256_d0.5` (183k params) → test
   0.7854 with bias²/MSE 1.0%, but best_epoch 380 ≈ max_epochs 400 (small nets are
   under-trained on val — sweep lr up to 1e-3). 2.1 grids the small-net neighborhood:
   width {96–256}, dropout {0.4–0.6}, lr {3e-4, 1e-3}, huber, mixup, late SWA.
4. **54-family is the bias champion but not the accuracy winner.** `w448x448_d0.3_gelu`
   test 0.7809 with bias²/MSE 0.04%; `w384x384_d0.3_gelu` test 0.7865 (n_seeds=1 in 2.0 —
   it missed the phase-2 cut; 2.1 gives it seeds). Small config budget: anchors + grids +
   SWA-late + mixup.
5. **OOD**: pure-96 keeps OOD strength (0.751) while the mixed family is
   in-distribution-strong but OOD-weak (0.03–0.13 on 8.9% OOD rows; its c1 = 54+10 half
   carries the 54-family's weak OOD). Not targeted by 2.1 (family allocation is pinned
   per the protocol), but re-reported so the trade-off stays on the record.

Success criteria (honest, val-based):
1. **Val-selected multi-seed winner test R² > 0.79** (2.0: 0.7903) **and/or val top-5
   ensemble > 0.805** (2.0: 0.8003).
2. **SWA fair re-test deploys SWA at least once** (best-SWA val < live best on val for
   ≥1 config) — proving the mechanism with the two documented fixes; if still never,
   record it as a negative with the fixes applied.
3. **Debias:** all three families' median bias²/MSE < 5% (2.0: 96-pool families still
   13.3% / 10.0%, 54-family 3.7%).
4. **Selection reliability:** 3-seed winners; mixed-family Spearman(val, test) no longer
   significantly negative; per-config seed consistency reported as a diagnostic.
5. **Reproducibility:** non-SWA anchors reproduce 2.0 bit-identically under v7 (stack
   check, max |diff| = 0); a `swa_late` config's live val curve equals its anchor's val
   curve (RNG-guard proof); `nb execute --uv` from `notebooks/`; README tables from stdout.

## 3. What's new in 2.1 (code changes vs 2.0)

### 3.1 `mlp21/trainer.py` — the two documented SWA fixes (headline change)
- **RNG guard:** the BN-recalibration forward pass (`_recalibrate_bn`, which runs the
  train loader in train mode so dropout consumes the shared RNG) is wrapped so the RNG
  state is restored afterwards (`torch.random.fork_rng(devices=[device])` + save/restore
  of `np.random`/`random` states). Consequence: a `swa=true` job's **live trajectory is
  bit-identical to its `swa=false` anchor** — verified by a pre-sweep stack check (anchor
  val curve == swa_late live val curve). This removes 2.0's documented "gains are
  live-trajectory artifacts" caveat and lets us attribute any `_swa_late` gains to SWA.
- **`swa_start_frac` becomes a swept knob** {0.7, 0.75, 0.8, 0.85} (2.0 hard-coded 0.6).
  With patience-60 and typical best-epochs 234–380, 0.85 × 400 = 340 risks never starting
  before early stop; the sweep tests all four values. Everything else in the trainer
  (patience-60, best-epoch selection, checkpoint/resume contract, deployment rule "SWA iff
  best-SWA-val < live-best") is unchanged.
- `mlp21/model.py`, `data.py`, `feature_groups.py`, `plots.py`: copied from `mlp20`
  unchanged; the `fg`/`plr` classes stay importable (winner-pool filter and grouping table
  stay valid) but **no configs use them** (documented negatives; no GPU re-spend).

### 3.2 Sweep driver — per-family phase depth + 3-seed winners + generated configs
- `run_mlp_sweep.py`: `phase2_top_n` / `phase3_top_n` may be an int (global) or a
  `{family: n}` dict so the mixed family (the winner, noisiest val) gets denser multi-seed
  coverage than 96/54. Phases run sequentially in one invocation (phase 1 → 2 → 3),
  resumable at each phase; `robust_ranking` metric stays `val_rmse`.
- **Phase 3 (new):** a 3rd sweep seed (123) for the top-M configs per family → the final
  winner is a **3-seed mean val RMSE** selection. This is the honest answer to 2.0's
  val-noise finding (seed-averaging, no test touching) and is exactly what "do more
  sweeps" buys us; the champion step then adds only {2024, 999} (5-seed ensembles).
- `make_configs.py` (committed): programmatically generates the 178-config list from the
  documented grid spec (section 5) and writes `config.yaml` — per the reproducibility rule,
  the sweep constants are produced by committed code, not hand-typed.
- `data_version: 8` (v6 = 2.0). *Deviation from plan:* the v7 config generator omitted
  `hidden_sizes` for `[384, 384]` configs (defaults fall back to `[256, 256]`), silently
  under-sizing 16 configs; fixed by always emitting `hidden_sizes` and bumping to v8 so
  the v7 artifacts are invalidated (see `make_configs.py` + config header).

### 3.3 Kept (proven) ingredients — unchanged from 2.0
huber δ {0.05, 0.1, 0.2} (+ mse); gelu/silu/relu; dropout 0.2–0.6; AdamW + warmup 5% +
cosine; grad clip 1.0; patience-60; seeds {42, 7} phase 1–2, +123 phase 3, +{2024, 999}
champion; aux2020 diagnostic; median-impute → StandardScaler → clip [−5, 5] fit on train
only; target in original units; `cudnn.deterministic=True`; batch 512 (batch-256 is a 1.3
negative).

### 3.4 Explicitly out of scope
- LOSO (per the 2.0 brief and "same protocol"); new routers (KMeans V0 stays for XGBoost
  comparability); station embeddings (LOSO leakage); new feature selection (96-pool /
  54-backbone / 10 deltas pinned); re-testing `fg`/`plr` (documented negatives — any spare
  GPU time goes to extra seeds, not to negatives).

## 4. Protocol (data_version 7, temporal only — same honest protocol as 2.0, denser seeds)

- Train on official train (2017–2020, n=9,803); early-stop/select on official val
  (2021–2022, n=4,805); evaluate on untouched test (2023–2025, n=6,620). aux2020
  (n=2,519) diagnostic only.
- Phase 1: seed 42 for every (family × config). Phase 2: seed 7 for the top-N per family
  by 2-seed-able val RMSE. Phase 3: seed 123 for the top-M per family → **3-seed mean val
  RMSE winner selection** (strictly more reliable than 2.0's 2-seed; no protocol-honesty
  change — val-only selection, aux2020 diagnostic, patience-60 unchanged).
- Winner pool = mlp/fg/plr (effectively mlp-only in 2.1 — no fg/plr configs run).
- Champion step: 5-seed {42, 7, 123, 2024, 999} ensembles of the top 1–2 winners (mixed
  first); offline val top-k (3/5/10) + cross-family ensembles, unchanged.

## 8. Risks & mitigations

- **SWA still never deploys even with the fixes** — the fixes make the test fair (later
  start, bit-identical live path); if equal-weight SWA still loses, record it as a
  negative (2.0 already showed the deployment mechanism is honest) and rely on the
  live-trajectory gains that were real in 2.0 (`w512x512x512_d0.3_huber0.1_swa` test
  0.7903 vs anchor 0.7789 — the RNG guard now lets us attribute such gains cleanly).
- **Mixed-family val noise persists** — structural mitigation: no fg/plr in the pool (the
  main 2.0 source of val/test disagreement), 3-seed winner selection (phase 3), and the
  honest val top-k ensemble reported alongside singles (ensembles were 2.0's strongest
  results).
- **~345 jobs is a long, failure-prone run** — resumable per phase (`--resume`), per-job
  logs under `artifacts/logs/`, `seed_complete`/`seed_resumable` invalidate-and-retry
  stale jobs, and per-family phase-depth trims; a single worker crash only costs that job.
- **Small-net 96-family exploration under-delivers** (best_epoch 380 suggests
  under-training) — the lr 1e-3 axis plus late SWA plus huber are the levers; anchors stay
  in the pool; debias is one of three 2.1 objectives.
- **1 h wall target missed (too long/short)** — phase counts and top-Ns are knobs; if the
  machine is slower than 2.0's, `--phase3-top-n`/`--phase2-top-n` trims keep it inside the
  2 h cap; if faster, extra seeds/champion configs can absorb the spare allocation.
- **2.0 committed** (`b7b68ad`, which also pre-created the empty 2.1 stub) — the
  `mlp20_reference_file` paths resolve and 2.1's reference rows load.

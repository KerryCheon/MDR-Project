# Feature-selection 2.2 error analysis and next-experiment handoff

## Interpretation boundary

The feature-selection 2.2 pipeline completed successfully. This document is a research analysis of the completed `final`, `nested`, `nested_locked_outer`, `crossed_candidates_locked_outer`, and `progressive_crossed_locked_outer` artifacts; it is not a runtime continuation note.

Every 2023–2025 result is retrospective. The recommendations below were developed after inspecting that period, so any experiment implementing them is also ineligible for an unbiased claim on 2023–2025. A new claim requires an untouched future-period and/or newly deployed ECE-station holdout.

Use [`README.md`](README.md) for the implemented architecture, [`RESULTS.md`](RESULTS.md) for the compact canonical result tables, [`PROTOCOL.md`](PROTOCOL.md) for the interpretation contract, and [`artifacts/report/`](artifacts/report/) for the normalized evidence behind this analysis.

## Executive diagnosis

1. The name-agnostic grouped-OOF selector corrected important methodological weaknesses in feature-selection 2.1.
2. The nested revision corrected candidate-generation leakage into the 2021–2022 outer period.
3. The remaining failure is not explained by feature count alone. Smaller and larger lists win under different end-to-end evaluation protocols and candidate trajectories.
4. The dominant observed problems are:

   - mismatch between the held-station selection protocol and the full-training aggregate diagnostic/reporting protocol;
   - unstable candidate trajectories after the first aggressive pruning step;
   - too little outer-year and station-coverage diversity;
   - temporal distribution and station-composition shift;
   - uncertainty estimates built from correlated fold and beta evaluations;
   - a hard-expert configuration that underperforms the global model, with its cause confounded by router-only inputs.

5. Feature-selection 2.3 should therefore be evaluation-first. Establish a stable global model before spending further capacity on experts.

## What worked and should be retained

- Station and date metadata define folds but do not enter the model matrix.
- Station-time folds exclude both future rows and the held station group.
- Paired permutation importance measures held-out predictive utility rather than pooled tree gain.
- Original column order provides a deterministic, feature-name-invariant tie-break.
- Required shared features give experts a common backbone.
- Nested candidate generation uses only 2017–2020 and does not read 2021–2022 labels.
- Saved configurations, split hashes, fold membership, atomic artifacts, and completion markers make the run auditable.
- Nested selection recovers much of the expanded-dataset global deficit relative to the original 2.2 arm, as a retrospective diagnostic.
- Progressive elimination shows that useful signal remains recoverable when the first pruning transition is less aggressive.

These are methodological and retrospective findings, not new SOTA claims.

## Error analysis

### The candidate protocols disagree; a metric-only cause is not established

The saved selector minimizes a cross-beta upper confidence bound on fold-level normalized RMSE after refitting for each held-station group. Each usable fold receives equal influence even though folds differ in row count and target variance. The candidate diagnostic called `outer` does something else: it fits once on all 2017–2020 stations, then scores the pooled 2021–2022 split. Its rank therefore changes both training geometry and metric aggregation.

The reconstructed same-geometry comparison separates those effects without retraining: it converts each saved held-station fold RMSE to squared error and pools the exact saved validation masks. The generated candidate-alignment summary reports every agreement count and mismatch arm. It shows that metric aggregation can change individual arm ranks, but does not explain the contrast between the held-station selector and the full-training aggregate diagnostic. That contrast is an end-to-end protocol mismatch.

Fold-normalized RMSE and row-pooled R² still encode different deployment priorities, but these artifacts do not isolate a damaging metric effect. Feature-selection 2.3 must declare its deployment objective first and compute primary and secondary metrics from the same OOF predictions and training geometry.

The crossed expanded-dataset winner also exposes path-transfer risk. Its grouped outer winner comes from the forward-time path because that tuple scores much better under the 2021–2022 grouped UCB, yet station-time candidates overtake it retrospectively. Retrospective ranks are useful for diagnosing instability, but must not choose a 2.3 configuration.

The original `validation_eval` is especially limited: original feature selection used the combined train and validation pool, so the later 2021–2022 score is a non-independent development re-score.

### Pruning history is part of the result

The pruning table shows the same large starting predictor pool for both datasets. The direct paths jump immediately to their first saved checkpoint, whereas the progressive path inserts data-derived bridge refits. The low progressive/direct overlap at common feature counts means that the later candidate list depends strongly on which correlated or interacting predictors survive the first transition.

Progressive forward-time elimination materially improves the retrospective derived_8.0 path. Together with the low overlap among original, nested, and crossed winners, this establishes sensitivity to validation geometry and elimination history. It does not establish repeated-seed selection stability: all current lists use one station partition and one model-seed policy.

The permutation-LCB table should be read carefully. Original rows describe the combined-development selector winner. Nested and crossed rows describe the saved inner candidate-generator winner; the outer chooser evaluates frozen lists and does not recompute permutation importance at its selected checkpoint.

### Temporal shift and bias are concentrated, not uniform

The target-distribution table shows a sharp expanded-dataset change in 2023 relative to the outer years. The nested expanded-dataset global model has strongly negative residual bias in that year, which weakens later. Residual is defined as truth minus prediction, so negative bias means systematic overprediction.

The corresponding derived_8.0 bias is much smaller. This supports an additional composition or calibration difficulty in the expanded station set, but the existing aggregate artifacts cannot separate climate shift, predictor-distribution shift, station-composition shift, and sensor behavior. Those mechanisms remain hypotheses until row-level predictions are joined to feature and station diagnostics.

Exponential recency weighting cannot be assumed to correct the shift. Its effect changes sign across arms and datasets and does not consistently reduce negative bias.

### Station coverage reveals deployment failures hidden by pooling

The generated station-selection, coverage, and error tables identify the negative-R² and maximum-RMSE cases without hard-coding station names. They also expose when a selected station has no outer-period observations, returns after a long observation gap, or has unusually low test-target variance. In such cases, a moderate absolute RMSE can produce an extreme station-level R².

The outer-fold audit distinguishes an assigned station from an observed station. A station can be listed in a held-out group while contributing no validation rows because other stations make the group usable; a group with no usable outer rows can disappear entirely. The current fold metadata records the group but not each assigned station's actual contribution.

The rule-selected stations have different diagnostic profiles even when they share a failure flag. Per-station R² must therefore always be read with row count, target dispersion, RMSE, and bias. Pooled overall metrics conceal these deployment-relevant failures.

### Beta is a training policy, not another fold observation

The saved selector pools beta variants from the same validation rows when estimating standard error. Those evaluations are paired and correlated; they should not increase the apparent effective fold count as if they were independent observations.

The retrospective beta table confirms that recency weighting helps some model/arm combinations slightly and harms others. It also fails to reduce negative bias consistently. In 2.3, beta must be a separately compared training-policy arm with paired uncertainty, selected only after the feature-ranking method and path are frozen.

### The MoE configuration fails, but the causal decomposition is incomplete

Frozen-router populations are not grossly imbalanced, and the saved regime deltas pass the outer paired-LCB admission rule. The deltas improve on the shared-only hard-expert model. However, the shared-only expert model is already substantially worse than the global model, and adding deltas does not recover that loss. Frozen versus refit routing changes the result much less than the global-to-expert gap.

The generated router-input coverage and summary tables expose an important confound: route assignments use inputs that are not all present in the compared predictor tuples. The artifacts establish that this hard-expert configuration loses to the global model; they do not establish that sample fragmentation is the primary cause or that routing adds no unavailable information.

Hard partitioning remains a plausible contributor because each expert receives fewer training rows, while router imbalance and delta selection alone do not explain the global-to-expert gap. A global model augmented with the complete router input set is required before attributing the loss among input access, route semantics, and sample fragmentation. The historical label `dynamic_k2_shared_plus_delta` is also misleading for nested evaluation: that row applies the saved frozen router. Future rows must name frozen and refit behavior explicitly.

## Root-cause classification

### Confirmed by saved artifacts

- The held-station selector and the full-training aggregate diagnostic rank candidates differently as end-to-end protocols.
- Under matched held-station geometry, the generated alignment summary shows that metric sensitivity exists, but it does not explain the nested selector versus full-training diagnostic contrast.
- Candidate paths are highly sensitive to elimination trajectory and fold family.
- The generated outer-coverage table records assigned development stations that contribute no observations to the outer validation period.
- Temporal bias is concentrated in particular retrospective years.
- Hard expert splitting loses substantially to the global model before regime deltas are considered.
- Beta effects are inconsistent across datasets, arms, and metrics.
- `nested_locked_outer` duplicates nested outer behavior under the current configuration.

### Strongly supported interpretations

- Fold-level normalized RMSE and row-pooled R² represent different deployment objectives, even though the current matched-geometry evidence does not show that distinction driving most winner changes.
- The first pruning jump discards useful correlated or interacting predictors.
- The available outer years are insufficient for a reliable station-time versus forward-time path choice.
- Treating beta-paired evaluations as independent understates uncertainty.
- Hard routing reduces the rows available to each expert and is a plausible contributor to the observed loss, but the current comparison is confounded by router-only inputs.

### Unresolved hypotheses

- Which predictor, climate, or sensor distributions cause the 2023 bias.
- Whether station composition or within-station climate shift is dominant.
- Whether conditional or correlation-aware permutation would stabilize correlated-feature ranks.
- Whether a higher-fidelity ranker improves selection enough to justify its compute cost.
- Whether soft or residual experts can outperform the global model.
- Whether hard-partition sample fragmentation, router-only information, or route semantics dominate the current MoE loss.
- Whether list instability is driven more by station assignment, model seed, or pruning history.

None of these unresolved hypotheses should be presented as a proven root cause.

## Decision-complete feature-selection 2.3 sequence

### Phase 0 — redefine the data contract

- Reclassify 2017–2025 as development-only data.
- Preserve all current 2023–2025 reports as retrospective references.
- Define the next untouched holdout as future years and/or newly deployed ECE stations.
- Keep fresh-holdout evaluation out of the normal development pipeline.
- Require a separate, explicit one-shot command after the model, features, beta, calibration, and reporting protocol are frozen.
- Evaluate MDR-v25, V3, 2.1 C1, and the chosen 2.3 model together on that holdout.

### Phase 1 — build evaluation infrastructure before selecting again

Persist one row per OOF prediction with:

- dataset, fold family, outer origin, and fold ID;
- station, date, and year;
- observed target, prediction, and residual;
- candidate ID, ordered-feature hash, and feature count;
- beta, model seed, and station-partition seed;
- router regime and route confidence/distance when applicable.

Compute from that ledger:

- primary risk: station-macro RMSE in soil-moisture units;
- secondary risk: pooled RMSE and pooled R²;
- robustness: worst-station and upper-quantile station RMSE;
- calibration: overall, yearly, and station bias;
- coverage: observed station-year blocks plus missing and returning stations.

Use paired station/year block resampling for uncertainty. Beta variants remain separate arms throughout.

### Phase 2 — repair validation geometry

- Generate multiple deterministic station partitions from saved seeds.
- Add multiple rolling outer origins instead of one development/outer boundary.
- Compare fixed-origin training, expanding-window training, pure future-time folds, future-time plus held-station folds, and returning-station gap folds that simulate outages identified by the generated station coverage.
- Record both assigned and actually observed validation stations.
- Reject a fold when its intended station-generalization case has no observations.
- Keep fold families separate in every report.

Use this predeclared robust selection rule:

1. Compute station-macro RMSE separately for each fold family and beta arm.
2. Estimate paired uncertainty with station/year block resampling.
3. Require a candidate not to regress materially on either forward-time or station-time risk.
4. Among statistically indistinguishable candidates, choose the smaller feature set.
5. Never consult a retrospective 2023–2025 ceiling.

### Phase 3 — stabilize ranking before choosing a count

Run sequential development-only ablations, not a full Cartesian sweep:

1. Direct versus progressive elimination.
2. Repeated station partitions and model seeds.
3. The current ranking learner versus a small number of higher-fidelity rankers.
4. Marginal permutation versus correlation-aware or conditional diagnostics.
5. Candidate-count stability only after the ranking method is fixed.

Generate checkpoint sizes reproducibly from the starting feature count while preserving the historical checkpoint region for comparison. Save the rule that generates sizes; do not add unexplained constants manually.

Report feature-list Jaccard, rank correlation, selection frequency, outer-risk distributions, and compute cost across seeds and folds. Progressive elimination is the default unless development-only paired evidence contradicts it.

### Phase 4 — choose the global model and beta

- Freeze the ranking method and candidate path before comparing beta.
- Evaluate beta 0.0 and 0.2 as separate model arms.
- Select beta from repeated outer folds using station-macro RMSE.
- Diagnose yearly and station bias from OOF predictions.
- If calibration is added, fit it only from development residuals and freeze it before fresh-holdout access.
- Retain the locked learner; broad XGBoost hyperparameter tuning is out of scope so the experiment isolates feature-selection changes.

### Phase 5 — gate MoE work behind the global result

The primary 2.3 model remains global. Continue MoE work only after the global feature set satisfies the predeclared development robustness requirements.

If continued, first compare the saved global feature set with a global-plus-all-router-input control under identical fitting and evaluation. Then compare the stronger global control, hard shared-only experts, global-plus-residual experts, and soft-gated residual experts. Shrink expert corrections toward the global prediction; persist route confidence, populations, predictions, and regime metrics; and require a positive paired improvement over the strongest global control with no meaningful worst-station regression. Improvement over shared-only experts is not sufficient. Freeze router preprocessing and use labels that distinguish frozen from refit routing.

### Phase 6 — freeze, then evaluate once

Before fresh-holdout access, freeze:

- split and station-coverage rules;
- primary, secondary, and robustness metrics;
- feature list and candidate count;
- beta and model parameters;
- optional calibration;
- router/expert architecture, if any;
- success thresholds;
- report code.

Run all historical baselines and the chosen model once on the new holdout. Any change after access creates a new experiment and requires another untouched evaluation source.

## Handoff decision

Do not start 2.3 by adding another candidate count or another MoE delta search. First implement the prediction ledger and repeated validation geometry, then stabilize progressive global ranking, then choose beta, and only then reconsider experts. The next unbiased performance claim belongs to a future-period or new-station holdout that remains inaccessible until this sequence is frozen.

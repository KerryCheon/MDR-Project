TEMPORAL MODEL IMPROVEMENT PLAN
================================

GOAL:
------
Increase test R² while stabilizing wet regime performance.
Current model: Transformer sequence model (v12.x line).
Baseline comparison: v7.4 stacked XGB+RF (R² ≈ 0.77).

We will test four controlled upgrade paths.


================================
OPTION A — STRONGER REGULARIZATION
================================

Objective:
Reduce overfitting and improve generalization (train 0.94 → test 0.53 gap).

Steps:
1. Increase dropout from 0.1 → 0.2 (if unstable, try 0.3).
2. Increase weight decay from 1e-4 → 1e-3.
3. Reduce model width:
   - d_model: 192 → 128
   - Keep nhead divisible (e.g. 4)
4. Add gradient clipping (if not already): clip_norm = 1.0.
5. Keep patience at 15 for early stopping.

Expected Result:
- Slight drop in train R²
- Improved val/test R² stability
- Reduced overfitting gap


================================
OPTION B — WET REGIME SAMPLING
================================

Objective:
Improve storm generalization without changing architecture.

Steps:
1. Identify wet samples using existing wet_masks.
2. Use WeightedRandomSampler in DataLoader:
   - Increase wet weight to 2.0–3.0
3. Keep loss function unchanged initially.
4. Compare:
   - Test overall R²
   - Test wet R²

Optional:
If unstable, try:
   - Smaller wet weight (1.5)
   - Or focal-style weighted MSE

Expected Result:
- Wet R² improves
- Overall R² may slightly increase
- Less negative wet regime behavior


================================
OPTION C — LONGER TEMPORAL MEMORY
================================

Objective:
Capture storm buildup and decay more effectively.

Steps:
1. Increase sequence length:
   - If currently 14 → try 21 or 30.
2. Keep architecture same.
3. Ensure no leakage in rolling features.
4. Compare:
   - Storm event R²
   - Worst decile performance

Important:
Sequence expansion must remain strictly past-only.

Expected Result:
- Better storm modeling
- Improved worst-decile metrics


================================
OPTION D — HYBRID ENSEMBLE (HIGHEST CEILING)
================================

Objective:
Combine Transformer temporal signal with strong tabular regressor.

Steps:
1. Train Transformer model (current best).
2. Train v7.4 stacked XGB+RF on same splits.
3. Save predictions from both models.
4. Train Ridge regression stacker on validation:
   Inputs:
      - Transformer predictions
      - XGB stack predictions
   Target:
      - True soil moisture
5. Evaluate stacked model on test set.

Expected Result:
- Increased stability
- Improved overall R²
- Wet regime partially rescued by boosting model

This likely has the highest ceiling.


================================
ORDER OF EXECUTION
================================

1. Run Option A (regularization sweep).
2. If improvement < 0.03 test R², move to Option B.
3. If wet remains negative, try Option C.
4. If none exceed v7.4 baseline, build Option D hybrid stack.

Do not change multiple things at once.
Log every run with metrics JSON artifact.
Compare only on identical splits.


================================
SUCCESS CRITERIA
================================

Minimum target:
- Test R² > 0.77 (beat v7.4 stack)

Stretch target:
- Test R² > 0.82
- Wet R² ≥ 0.0
- Worst decile R² > 0

If achieved:
Model becomes publication-grade temporal component.

TEMPORAL FAMILY SIGNAL DIAGNOSTIC PLAN

Goal:
Quantify how much predictive signal each feature family contributes
before attempting index compression or architectural changes.

------------------------------------------------------------
PHASE 1 — FAMILY STRUCTURE ANALYSIS
------------------------------------------------------------

For each feature family (A–I or however defined):

1) Redundancy / Compression Analysis
   - Compute correlation matrix within family
   - Compute mean |corr|
   - Run PCA:
       - % variance explained by PC1
       - % variance explained by top 3 PCs
   - Compute mutual information vs target

Output:
- Table:
    family | n_features | mean_abs_corr | PC1_var | MI_mean | MI_max

Purpose:
- Identify highly compressible families
- Identify noisy/diverse families
- Identify low-signal families

------------------------------------------------------------
PHASE 2 — SINGLE-FAMILY XGBOOST EXPERIMENT
------------------------------------------------------------

For each family F:

Train:
    XGB_F → soil_moisture_5cm

Rules:
- Use identical hyperparameters across families
- No soil_moisture lags
- No cross-family features
- Same train/val/test splits

Track:
- Train R²
- Val R²
- Test R²
- Wet R²
- Worst decile R²
- RMSE
- Bias

Output:
- Ranked table of families by Test R²
- Separate ranking by Wet R²

Purpose:
- Determine predictive hierarchy of processes
- Identify families that dominate
- Identify families that add little signal

------------------------------------------------------------
PHASE 3 — FAMILY COMPRESSION TEST
------------------------------------------------------------

For strong families only:

Compare:
1) Raw family features
2) PCA compressed (top 1–3 components)
3) Physically derived index (custom formula)

Evaluate performance drop or retention.

If compressed ≈ raw:
    Compression is valid.
If large drop:
    Family contains multi-dimensional signal.

------------------------------------------------------------
PHASE 4 — REBUILD WITH STRUCTURE
------------------------------------------------------------

Based on results:

Option A:
    Keep only top K families.

Option B:
    Replace high-redundancy families with PCA index.

Option C:
    Use family-level embeddings in NN.

------------------------------------------------------------
OUTCOME
------------------------------------------------------------

This experiment answers:
- Which physical processes truly drive prediction?
- Whether index-building is justified.
- Whether deep modeling is even necessary.
- Where model instability originates (wet regime likely).

This moves from model tweaking to structured signal attribution.
